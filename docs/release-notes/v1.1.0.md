## FreeDyn v1.1.0

### Bundled FreeDyn Core: v1.0.5 (upgraded from v1.0.4)

**New Features**
- **C-API:** Measure derivatives w.r.t. generalized velocities via the new `getMeasureDerivativeQd`. `getMeasureDerivative` now reports `oSuccess = 0` for unknown labels instead of returning a silent zero row.

**Bug Fixes**
- **Parameters:** All DataObject parameters got the ID `"unassigned"`, so `set_parameter()` via the API always modified the first parameter when a model had several. Models saved with `"unassigned"` IDs get fresh IDs when loaded in the GUI.
- **Splines:** Spline evaluation used a stale interval on reruns (second `solveEoM` in the same process) and after rejected time steps, so reruns gave different results than the first run. Zero-clamped cubic splines no longer read beyond the end of their coefficient vectors.
- **Measures:** Wrong `dS/dq` of XYZ displacement and XYZ velocity measures w.r.t. ground.
- **Measures:** Angle measures delivered ambiguous initial values (0 vs. Pi, -Pi vs. +Pi). They now use `atan2` with full revolution counting, and the tracking state is fully reset on each simulation start.
- **Solver (HHT):** The corrector rejected steps when residuals were at floating point noise level, e.g. for a system at rest with rotated principal axes of inertia.
- **Data model:** Fixed formatting of data model block keys.

---

### Python Bindings

**New Features**
- **Measure derivatives:** `Model.get_measure_derivative(name, wrt="q" | "qd")` returns `dS/dq` or `dS/dqd` as a row of shape `(1, numGeneralizedCoordinates)`. Verified against central finite differences (max. rel. error 8e-10).
- **One wheel for all Python 3 versions:** The package now ships a single `py3-none-win_amd64` wheel. Tested on Python 3.12, 3.13 and 3.14.

**Performance**
- Arrays are passed to the DLL as plain pointers created once, instead of `ndpointer` checks on every call. Measured on a small model: `Model.fetch_states_at_index` about 9x faster, `ModelRelatedMatrixBuffer.update_from_dll` about 7x, `ForceParameterDerivativeMatrixBuffer` and the vector buffers about 2x. Idea and first implementation by Philipp Zallinger.

**Bug Fixes**
- **Crash:** `get_parameter_names()` allocated a 256-byte label buffer, but the DLL writes 512 bytes. The overflow corrupted the Python heap and could crash the interpreter later during garbage collection, e.g. when using `ForceParameterDerivativeMatrixBuffer` together with a matrix buffer.
- **argtypes conflicts:** All C-API signatures are now declared once when the DLL is loaded. Previously different parts of the bindings set different `argtypes` on the same DLL function.
- **Input checks:** Non-contiguous arrays now raise `TypeError` instead of silently passing the wrong memory to the DLL.
- **Wheel:** GUI-only DLLs from former builds are no longer packaged (wheel 97 MB instead of 102 MB).

### MATLAB / Simulink

**Bug Fixes**
- `freedyn_api.m` ported to the current C-API. It still called removed functions and old signatures, so most calls crashed. New: `getMeasureDerivative(label, 'q' | 'qd')`, `updateSystemAtTimeIndex`, `resetActiveModelForRerun`, matrices returned as MATLAB sparse, zero-based time indices like in Python.
- Simulink template `sfun_BLANK.c` uses the current exports and reports an error status instead of calling a missing function.
- Note: the MATLAB changes were checked against the C header but have not yet been run in MATLAB.
